# Changes — 2026-09-24

Summary of the fixes applied on 2026-09-24 to get joint-space hand-guiding
working cleanly on the real Gen3 6DOF, plus a parameter reference for tuning.
See `src/admittance_control/ARCHITECTURE.md` for the full design rationale —
this file is the changelog + the "how do I change X" quick reference.

## What changed today

1. **Fixed 6–7 Hz oscillation at full vertical extension.**
   Added `velocityTau` (first-order lag / virtual inertia on the commanded
   velocity) and `inertiaScaling` (per-joint gain scaled by
   `H_ii(stance)/H_ii(q)`) to `HandGuideState`. High-frequency velocity RMS
   at full extension dropped from 0.173 rad/s to 0.023 rad/s in logged test
   data.
2. **Fixed a segfault on the first control tick.** The payload-compensation
   Jacobian's output buffer (`payload_jac_full_`) wasn't pre-allocated before
   `rbd::Jacobian::fullJacobian` wrote into it. Fixed by allocating it once at
   init: `Eigen::MatrixXd::Zero(6, nrDof)`.
3. **Fixed `SAFETY GATE` false trips on continuous joints past ±180°.** The
   Kortex driver reports joint_1/4/6 wrapped to `[-pi, pi]`; the mc_rtc model
   does not wrap. Added `angleDiff()` (`std::remainder`-based) and routed
   every model-vs-encoder comparison (safety gate, first-command check,
   per-cycle clamp) through it. The published command is now always
   expressed as "encoder + clamped delta", so it's automatically in the
   encoder's own wrapping.
4. **Fixed joint_4/joint_6 being artificially limited to ±2.45/±2.0 rad.**
   The local mc_kinova 6-DOF patch had inherited 7-DOF joint-limit overrides.
   joint_1, joint_4 and joint_6 are true infinite-rotation actuators on the
   6-DOF arm (no mechanical stop, `continuous` in the URDF); only joint_5
   (spherical wrist 2) has a real physical limit (±2.09 rad = ±120°). Fixed
   in `patches/mc_kinova/mc_kinova_6dof.patch` — see
   `patches/mc_kinova/README.md` for how to (re)apply and rebuild.
   Verified on hardware: joint_4 rotated 606° (1.7 turns, crossing ±180°
   twice) with model/encoder staying within 0.014 rad and no gate trips.

All four are independent fixes; (1) is about *how smoothly* the arm moves,
(2)–(4) are about *not stopping/crashing* under specific conditions
(startup, angle wrap, joint limits).

## Parameter reference

### Bridge ROS 2 parameters (`kortex_mc_rtc_bridge_admittance`)

Set in `src/admittance_control/launch/admittance_real.launch.py`. Changing
these requires only relaunching the bridge node (no rebuild) if you edit the
values passed on the `ros2 run`/`ros2 launch` command line; edit the launch
file's `parameters=[{...}]` dict to change the committed defaults.

| Parameter | Default | Meaning |
|---|---|---|
| `dry_run` | `True` | If true, everything runs (estimation, logging, gates) but the final command is never published. Flip to `False` only after confirming gate/estimator behavior in the logs. |
| `torque_sign` | `-1.0` | Sign flip between RBDyn's torque convention and what `/joint_states.effort` reports on this driver. |
| `deadband_torque` | `0.5` Nm | Soft deadband threshold on the filtered external-torque estimate, per joint. |
| `qd_gate_low` / `qd_gate_high` | `0.5` / `2.0` rad/s | Per-joint velocity gate: torque reading is scaled to 0 once `|qdot|` reaches `qd_gate_high`, linearly from 1 at `qd_gate_low`. |
| `delta_max` | `0.02` rad | Max per-publish-tick position delta from the current encoder reading — a hard velocity cap independent of the FSM's output. |
| `model_real_gate` | `0.05` rad | Safety gate: if model vs. encoder deviate more than this on any joint, stop publishing entirely until it clears. |
| `publish_rate` | `200.0` Hz | Target publish rate to the trajectory controller (decimated from the control rate if control rate > publish rate). |
| `payload_mass` | `0.9` kg | Point-mass gripper payload model, for gravity compensation. |
| `payload_com` | `[0.0, 0.0, -0.12]` m | Payload point offset from `bracelet_link` origin. |
| `payload_body` | `"bracelet_link"` | Body the payload is rigidly attached to. |
| `accel_filter_tau` | `0.1` s | Low-pass time constant on the finite-differenced joint acceleration used in inverse dynamics. |

**To change:** edit the `parameters=[{...}]` block in
`admittance_real.launch.py`, then `colcon build --packages-select
admittance_control` (launch files are Python and get installed, so a rebuild
is technically only needed if you don't `source` a symlink install — safest
to always rebuild) and relaunch.

### `HandGuide` FSM state parameters (`etc/KinovaHandGuiding.yaml`)

| Parameter | Default | Meaning | GUI-live? |
|---|---|---|---|
| `admittance` | `[0.05, 0.05, 0.05, 0.08, 0.08, 0.08]` | rad/s commanded per Nm of estimated external torque, per joint (`joint_1`…`joint_6`). Wrist joints get more admittance since a given hand force produces less torque there. | Yes |
| `maxJointVel` | `0.5` rad/s | Hard cap on commanded joint velocity. | Yes |
| `holdTorque` | `0.5` Nm | Below this (max over joints), latch into HOLD. | Yes |
| `guideTorque` | `1.0` Nm | Above this, switch into GUIDING. Hysteresis vs. `holdTorque` prevents chatter at the boundary. | Yes |
| `stiffness` | `100.0` | `PostureTask` position gain `K`. | Yes |
| `damping` | `20.0` | `PostureTask` velocity gain `D`; commanded velocity converges to `refVel` with time constant `1/D` (50 ms at default). | Yes |
| `weight` | `100.0` | `PostureTask` QP weight relative to other tasks/constraints. | No (constructor-only) |
| `velocityTau` | `0.15` s | First-order lag on the commanded velocity (virtual inertia). Larger = smoother but slower to respond; added to fix full-extension oscillation. | Yes |
| `inertiaScaling` | `true` | Enable per-joint gain scaling by `H_ii(stance)/H_ii(q)`. | Yes (checkbox) |
| `inertiaScaleMin` / `inertiaScaleMax` | `0.15` / `1.0` | Clamp range for the inertia-scale factor. | No (YAML only) |

**To change (persistently):** edit
`src/admittance_control/etc/KinovaHandGuiding.yaml`, then
`colcon build --packages-select admittance_control` and restart the
controller (relaunch the bridge, since it owns the `MCGlobalController`
instance).

**To change (live, while running):** use the mc_rtc GUI panel → `Control`
category, while in the `HandGuide` state. Changes marked "GUI-live" above
apply immediately and can be tuned with the arm running; they revert to the
YAML value on the next relaunch unless also written back to the YAML.

### Where the control-loop timestep actually comes from

`Timestep: 0.005` (200 Hz) must agree across three places, and the bridge
enforces this by reading it from the loaded controller rather than hardcoding
it (`loop_dt_ = gc_->timestep();` in `jointStateCallback`):

- `~/.config/mc_rtc/mc_rtc.yaml` (or `/usr/local/etc/mc_rtc.yaml`) —
  **this is the file actually loaded** by `MCGlobalController()`.
- `src/admittance_control/etc/mc_rtc.yaml` — in-repo copy for reference
  only; **not read at runtime**, keep it in sync by hand.
- `src/admittance_control/etc/KinovaHandGuiding.yaml`'s `Timestep:` field —
  informational; also not authoritative.

If you need to change the control rate, edit
`~/.config/mc_rtc/mc_rtc.yaml` directly on the machine that runs the bridge.

## Diagnostics added

- `/admittance/tau_ext` and `/admittance/tau_ext_raw` (`Float64MultiArray`,
  6 values, `joint_1`…`joint_6` order): post- and pre-filter/deadband
  external torque estimate, for external logging without needing the mc_rtc
  binary log.
- mc_rtc log entries `HandGuide_tau_ext`, `HandGuide_qdot_des`,
  `HandGuide_holding`, `HandGuide_inertia_scale`, `HandGuide_H_diag` —
  written to `/tmp/mc-control-KinovaHandGuiding-*.bin`, convert with
  `install/bin/mc_bin_to_log <bin> <csv>`.
- Periodic (every 500 ticks) info logs of raw vs. filtered `tau_ext` and the
  worst-case model-vs-real joint deviation.
- Loop-period warning if the control loop's actual mean/max period drifts
  more than 20%/5x from the configured `Timestep`.

## Verification (2026-09-24, ~90 s hardware run)

- joint_4: 606° of travel (1.7 turns), crossed ±180° twice, model/encoder
  deviation stayed ≤0.014 rad throughout, zero `SAFETY GATE` trips.
- joint_2/3/5: 139°/213°/140° of travel, tracked within ≤0.01 rad (one
  isolated 0.58 rad single-tick spike traced to a single dropped/malformed
  `/joint_states` sample, not a control issue).
- High-frequency velocity noise: 0.001–0.007 rad/s across all joints (below
  the 0.023 rad/s post-fix baseline from the extension-oscillation fix).
- Control loop: steady 5.00 ms period throughout.
